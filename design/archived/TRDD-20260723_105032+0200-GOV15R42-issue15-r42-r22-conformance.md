## Problem

ai-maestro server governance-conformance audit (#15, vs GOVERNANCE-RULES.md v4.5.0)
found: **F1 (MAJOR, load-bearing)** — persona Forbidden-action #6 carved an
"unless the user or MANAGER EXPLICITLY instructs" exception covering `tmux
send-keys`, which violates **R42** (IRON/ABSOLUTE: no agent may inject a
keystroke into another agent's session; no title exempt; a superior's directive
is a MESSAGE, not a keystroke). **F2 (MINOR)** — the R22 self-id line + `Agent:`
commit trailer were mandated only for AMP, not uniformly for GitHub writes.

## Fix (commit pending; persona edits)

- **F1:** split Forbidden-action #6 into two rules — (#6) ABSOLUTE keystroke/
  command/prompt injection ban into ANOTHER agent's session by tmux/CLI/API, no
  user or MANAGER authorization (R42.1/R42.2), driving your OWN session fine
  (R42.4); (#7) lifecycle (kill/hibernate/wake/restart another agent) is
  MANAGER/COS authority (R42.6), server 403s regardless. Renumbered old #7–#10 →
  #8–#11 (no index references anywhere — verified by grep).
- **F2:** added a standing R22 line to ALLOWED ACTION #2 — every GitHub write
  (issue/comment/PR body/PR review/discussion/release note) begins with the
  self-id line, and every commit carries `Agent: ai-maestro-autonomous-agent`
  (R22.1–R22.3); AMP self-id covers AMP only.
- **Guard:** two content-invariant tests
  (`test_persona_keystroke_injection_is_absolute_no_manager_exception`,
  `test_persona_r22_self_id_and_agent_trailer_uniform_on_github_writes`).

This TIGHTENS security (R42 is IRON) — it relaxes nothing. `relevant-rules`: S3.1
(tests), S5.1 (persona/governance edit), S7.1 (self-id on GitHub writes — F2 is a
direct instance).
