### FIX — a claim of ours was wrong, missing, or had the hole the host just closed

- **The secret predicate had the hole 2.1.248 fixed in the host.** 2.1.248 stopped
  `/ultrareview` and locally seeded cloud sessions uploading uncommitted `prod.env`-style
  files, `*.tfvars`, and editor swap/temp/backup COPIES of credential files
  (`key.pem.tmp`, `id_rsa.swo`). Our own "never read secrets" rule matched only
  `.env`/`.env.local` plus names containing `token|credential|password|secret|private_key`
  — so a `.tmp`/`.swp`/`.swo`/`.bak`/`~` suffix, a `*.tfvars`, and a literal `prod.env`
  all walked straight through it. Widened in all three places that restate the predicate:
  the persona's FORBIDDEN item 3, the governance skill's `questions.md` Q4, and the
  isolation skill's `layers.md` secret row. This is the richest pattern in a sweep: when
  the host hardens its own boundary, check ours for the same defect.
- **A sub-agent's cross-session reply never reaches the sub-agent.** 2.1.248: a
  `SendMessage` sent by a sub-agent goes out under the PARENT session's address, and any
  reply is delivered to the parent's conversation. A sub-agent told to ask a peer session
  a question and wait waits forever while the answer lands in the coordinator's
  transcript.
- **`--restricted` narrows the persona from outside it.** 2.1.248 added `--restricted` /
  `CLAUDE_CODE_RESTRICTED=1`: command- and code-running tools and `WebFetch` removed,
  file tools confined to the working directory, `bypassPermissions` REFUSED, and user,
  project and local settings files IGNORED. Three consequences worth stating: the
  writable roots are narrowed to cwd by the host; an approval mode you think you hold may
  not exist; and with settings ignored, the project's hooks and rules do not load at all,
  so an unattended run there is running without the guardrails it assumes.
- **Cross-session availability and a new visible HOLD.** 2.1.248 made
  `SendMessage`/`ListAgents` work on Bedrock, Vertex and Foundry and with telemetry
  disabled, and made an INVALID `crossSessionInbound` value warn and hold (user settings)
  or refuse (managed) rather than fail quietly.
- **A refresh-lock collision is a retry, not a logout.** Before 2.1.248 a session whose
  token expired while another Claude Code process held the OAuth refresh lock was sent to
  the login screen — an unattended run ended with nothing for `CLAUDE_CODE_RETRY_WATCHDOG`
  to act on. It is now a retryable error. This host runs several Claude Code processes and
  an external credential rotator, so it is the exact collision that used to end runs.

- **A CI run now gets the workspace trust prompt.** Before 2.1.248 `claude agents`
  SKIPPED the workspace trust prompt when the `CI` environment variable was set. That is
  fixed, so the prompt now appears — an automated or CI-spawned run that relied on `CI=1`
  to sail past trust now stops and waits for a human.
- **A background session resumed after the machine was off now asks first.** The agent
  view could silently resurrect a weeks-old background session; it now shows it as
  stopped at its real end and ASKS before resuming the saved conversation. A long-parked
  background session is no longer hands-free to bring back.

### DELIBERATELY NOT DONE

**`experimental.cacheTtl: "1h"` was drafted onto the shipped agent, then REVERTED.**
2.1.248 added a per-agent prompt cache TTL, and this persona drives long unattended runs,
so `"1h"` looked right. It is not shippable: the key is still `experimental.`, its
interaction with the default TTL is host-version dependent, and a shipped plugin pinning
a TTL bakes one host's cache economics into every installer's config for zero
stale-claim value. Revisit if the key loses the `experimental.` prefix.

**`--restricted` was documented even though the persona never mentioned the flag**, which
is the same shape as the `/loop` entry discarded just below. The exception is deliberate:
`/loop` only widens where an existing feature is available, whereas `--restricted` can
silently narrow the writable roots, void an approval mode, and stop the project's hooks
and rules from loading at all — an unattended run needs to be able to detect that.

**Entry 37 (a backgrounded worktree session now holds the worktree lock) is a verified
no-op**: `grep -rn "worktree remove"` across `agents/`, `skills/` and `README.md` returns
nothing, so no shipped claim advises the cleanup this protects.

`/loop` self-paced dynamic mode and the no-prompt autonomous default became available on
every provider in 2.1.248. The persona never mentions `/loop`, so there is no stale claim
to fix — documenting it would be NEW scope, not a sync. Recorded here instead.
