# TRDD-CPV320UP — Adopt CPV v3.2.0 + make the three-way pin parity real

## ⏵ STATE — READ THIS FIRST ON RESUME (authoritative) — 2026-07-23

- **IN PROGRESS.** Successor to TRDD-R7NK2VQD (which migrated the pipeline onto the
  v3.x canon and pinned the CPV gates to v3.1.0).

  and the unit suite, commit. Then decide publish (USER-gated).

## Problem (all facts VERIFIED)

1. **CPV v3.2.0 released 2026-07-23T12:37:56Z** (stricter taint engine — new FN catch
   on bare `ast.Attribute` sources in augmented assignment; CC 2.1.217-218 spec sync;
   dead-code removal). The pipeline is pinned to **v3.1.0** → out of date.
   Verified the plugin PASSES the v3.2.0 `--strict` gate locally: `EXIT=0,
   CRITICAL=0 MAJOR=0 MINOR=0 NIT=0, WARNING=4` (the stricter taint flags nothing).
2. **The three CPV gate sites do NOT actually agree.** `release.yml`'s own comment
   asserts "all three MUST agree ... pinned to the SAME CPV tag as ci.yml's validate
   job and publish.py's local gate." VERIFIED FALSE: `ci.yml:196` and `release.yml:92`
   pin `@v3.1.0`, but `publish.py`'s three gate calls (Steps 4/5/5.5, lines
   1683/1697/1720) are **UNPINNED** — they float to the CPV default branch (now v3.2.0).
   This is the recurring "a guarantee stated more broadly than the mechanism delivers"
   defect class (memory `publish-pipeline.md` [^8]): a floating local gate is also
   NON-REPRODUCIBLE — its result depends on when CPV last released, not on any commit
   here.
3. **One new v3.2.0 finding, in code from THIS session:** `scripts/gitignore_rules.py`
   (extracted in TRDD-CPVXTRCT) has a shebang but is not executable, while its sibling
   `scripts/gitignore_filter.py` (same extraction, same import-only shape) carries
   shebang + the executable bit. The extract dropped the +x bit.

## Fix (decision recorded per alternative)

- **Bump all three CPV pins v3.1.0 → v3.2.0** (`ci.yml` code + comment, `release.yml`
  code, `publish.py` × 3).
- **PIN publish.py's three gate calls to `@v3.2.0`** rather than leaving them floating.
  - *Why not keep floating* ("local gate is always the strictest"): a float is
    non-reproducible and contradicts release.yml's documented "all three agree"
    invariant — the very property that lets the pinned CI/release nets trust the local
    gate. Rejected.
  - *Why not a single-source-of-truth version file read by all three*: it moves the
    version into YAML `$(cat .cpv-version)` file-reads that can only be verified by a
    real CI run (I am holding the push until locally verified), and it adds pipeline
    surface for a value that changes a few times a year. Over-engineering for now;
    recorded as a future candidate. The explicit pin + a cross-reference comment at
    each site is fully locally-verifiable and makes the invariant true today.
- **`chmod +x scripts/gitignore_rules.py`** (git tracks the mode) — restores the +x the
  extract dropped, matching the sibling's shebang+executable convention and CPV's own
  recommendation. Not shebang-removal: the sibling sets the in-repo convention.
