## Sweep findings

Triaged per `[[claude-code-version-sync]]`: every entry against all four on-mission axes
(write scope · sub-agent propagation · approval provenance · unattended survival) AND the two
documented blind spots (identity/addressing drift; an entry whose only effect is a new
permission prompt).

### FIX — one shipped claim falsified

- **Persona ~L502**, the "a send is NOT a delivery" paragraph, argued the cross-session
  channel is unreliable by citing 2.1.224's fix for `SendMessage` reporting success on a write
  that had actually failed. Upstream closed that entire family: **2.1.234** reports a session
  list too long to check completely (instead of treating unseen sessions as absent),
  **2.1.235** refuses an oversize message up front (instead of silently dropping it),
  **2.1.238** reports `refused` when the recipient's `crossSessionInbound` refuses AND reports
  an inbox DROP (rate limit / full queue), **2.1.240** made `/`-titled sessions addressable
  again. An agent reading the old paragraph would over-distrust a channel the host had already
  fixed, and would read silence as uninformative when silence now carries information.
  **Narrowed, not dropped** — what survives is the actual R6 argument: `crossSessionInbound`
  set to HOLD is accepted-not-delivered, a dialog can still expire, and the transport still has
  no server-side route validation and no server-side record.

### FIX — three gaps the persona/README did not close

- **Persona, identity/addressing drift (blind-spot class 1).** 2.1.240 made `ListAgents` richer
  — a session now sees its own name as peers address it, and live teammates that previously
  looked absent. Recorded next to the existing "a listing is not a licence to contact" rule:
  it widens what you can SEE, never what you may contact.
- **Persona, unattended survival.** 2.1.236 added `notify_when_idle` to cross-session
  `SendMessage` — a one-shot, opt-in notice when a session next goes idle. An unattended run
  waiting on a peer otherwise polls `ListAgents` in a loop, spending the turn budget the run
  exists to conserve. Added as a delegation bullet; a notice is still not authority.
- **README, new-permission-prompt class (blind-spot class 2).** 2.1.238 made an MCP
  `headersHelper` in a project `.mcp.json` — and inline MCP servers in project or `--add-dir`
  agent files — require that folder's trust dialog, **including under `claude -p`**. This is
  the same failure shape as the 2.1.232 nested-repo trust entry already documented: a fresh
  clone stalls an unattended run at the moment it is ENTERED. Nearly dropped, because it
  touches no writable root and reads as a no-op under the write-scope axis — exactly the
  failure the `[[claude-code-version-sync]]` `[^2]` lesson predicts.

### FIX — supporting evidence gone stale

- **workspace-isolation SKILL + layers.md** argue that a string-compare scope check is not a
  scope check, evidenced by Claude Code fixing that class three times (2.1.212/216/217). The

  the host now owns that one case; the heartbeat still owns every other (a session that died

- **README**, same area: **2.1.240** made `CLAUDE_CODE_RETRY_WATCHDOG` fail immediately on

## Release

Shipping is blocked on a decision only the USER can make, and this card must not claim
otherwise. `git push` to origin is refused by `.githooks/pre-push` (strict publish policy,
caller verified by process ancestry), so delivering these commits means cutting a release via
`scripts/publish.py`.

Measured this session, because two peer sessions broadcast conflicting claims about it:
`scripts/publish.py` DOES rewrite `.githooks/pre-push` (L194-195) from an inline
`PRE_PUSH_HOOK_TEMPLATE`, and that template is **byte-identical** to the live hook —
AST-extracted and compared by sha256 (`3cfa9716f6f31809`, 82 lines both sides). So a release
regenerates the hook to the same bytes: it neither no-ops the hook nor adopts CPV v5.4.0's
branch-aware form. The CPV pin is already `v5.4.0` at five sites (publish.py ×3, ci.yml,
release.yml), guarded by `tests/test_cpv_pin_parity.py`.

Adopting the branch-aware hook is therefore a SEPARATE change (bump the template, correct the
hook's own header, fix or delete the dead `git-hooks/` install path) and is not folded in here.
